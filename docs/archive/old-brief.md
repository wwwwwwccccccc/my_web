# 个人生活记录网站 · 需求文档 v0.1

> 文档用途：作为个人生活记录网站第一版开发与上线的需求依据。  
> 技术方向：React + Vite，静态站点，优先预渲染 / SSG。  
> 上线目标：1 周内上线第一版。  
> 成本目标：每月 100 元以内，实际预计 5～10 元/月。  
> 主要访问地区：中国大陆。  
> 当前版本定位：先上线可用第一版，复杂功能后续迭代。

---

## 1. 项目目标

做一个以 **旅行、工作项目、成长经历、照片相册、家庭记忆、时间线** 为内容的个人记录站，整体气质偏复古，中文为主、英文为辅。

当前仅自己可见，未来允许家人朋友共同编辑；访客只能浏览公开内容，不能评论。

以 **React + Vite** 实现，**1 周内上线第一版**，每月成本控制在 **100 元以内**，主要访问地区为中国大陆。

## 2. 用户与权限

| 角色 | 当前 | 未来 | 权限 |
|---|---|---|---|
| 站长（你） | 唯一内容创作者 | 保留 | 发布、编辑、删除、设置公开/私密 |
| 家人/朋友 | — | 可能加入共同写 | 需要单独设计“协作编辑”方案，第一版不做 |
| 访客 | 仅浏览 | 仅浏览 | **不能评论**，只能看公开内容 |

### 关键决策

你回答“目前仅给自己看，部分公开、部分私密”。在纯静态站上，“仅自己看”和“部分私密”需要拆开理解：

- **公开内容**：任何拿到链接的人都能访问。
- **私密内容**：如果坚持“不登录就完全看不到”，纯静态站做不到真正的访问控制，只能做 **客户端密码解锁**（内容加密后打包进页面，输入密码后在浏览器里解密）。这种方式能挡住普通访客，但 **不能防技术手段**，也不适合放极度敏感的信息。
- **建议的第一版定位**：私密内容 = “带密码的隐藏页”，而不是“银行级保密”。如果未来有真正的多用户登录和权限管理需求，需要引入后端或 BaaS，这会超出一周范围。

## 3. 内容模型（第一版够用即可）

| 内容类型 | 字段建议 | 备注 |
|---|---|---|
| 旅行 | 标题、日期、地点、正文、封面图、相册引用、标签 | 可按“年份/地区”归档 |
| 工作项目 | 标题、时间范围、角色、简介、正文、配图、标签 | 可设为公开或私密 |
| 成长经历 | 标题、日期、正文、标签 | 以时间线方式串联 |
| 照片相册 | 相册名、封面、照片列表、每张照片的说明/日期/地点 | 瀑布流或拍立得卡片展示 |
| 家庭记忆 | 标题、日期、正文、照片、标签 | 默认建议私密 |
| 时间线 | 自动从上述内容中提取“日期 + 标题 + 类型” | 不做手动录入，减少维护成本 |

### 多语言

界面文案（导航、按钮、日期格式）做中/英切换；**内容本身**建议第一版只写中文，英文版留空或仅翻译“关于我”和首页简介。

内容级双语的工作量远大于界面双语，一周内不建议铺开。

## 4. 功能清单（必须 / 可选 / 暂不做）

### 4.1 必须（第一版）

1. **首页**：复古风格门面，展示最新内容、简介、进入时间线的入口。
2. **关于我**：自我介绍 + 可替换的占位图片。
3. **相册**：按相册分组，支持点击看大图，图片懒加载。
4. **时间线**：自动聚合旅行、工作、成长、家庭记忆的日期条目。
5. **分类/标签**：给内容打标签，标签页可筛选。
6. **公开/私密标记**：每篇内容可勾选“公开”或“密码访问”。
7. **中/英界面切换**。
8. **微信分享基础**：每篇公开内容生成正确的 `og:title` / `og:description` / `og:image`，保证在微信里分享时显示卡片而不是裸链接。
9. **访问统计**：能看到总访问量、热门页面即可。
10. **内容用 Markdown 或 JSON 管理**，改内容不需要动组件代码。

### 4.2 可选（第一版来不及就第二版）

- 站内搜索（静态站可以做前端全文搜索，但一周内不是最高优先级）。
- RSS 订阅。
- 数据导出按钮。
- 更精致的复古交互动效（如翻页、纸张纹理、拍立得反光）。

### 4.3 暂不做

- 访客评论。
- 多用户登录与协作编辑。
- 真正的服务端权限控制。
- 视频/音频托管（会显著增加成本和复杂度）。

## 5. 页面结构

```text
/                   首页
/about              关于我
/albums             相册列表
/albums/:slug       单个相册
/timeline           时间线
/tags/:tag          标签筛选页
/posts/:slug        内容详情页（旅行 / 工作 / 成长 / 家庭记忆共用）
/private/:slug      私密内容解锁页（密码后解密正文）
```

导航保持极简：**首页 / 相册 / 时间线 / 关于我**。

联系我可以用“关于我”页里的一个邮箱链接代替独立页面，减少一个页面的开发和维护。

## 6. 复古风格参考

你要求“现成的图片或网站放给我看看”。下面这几个是真实可访问或可看源码的项目，按视觉方向分类。

建议你逐个打开，挑一个作为主参考，再告诉我“喜欢哪个、讨厌哪个”，据此把设计方向写进需求文档。

### 方向 A：8-bit / CRT 像素复古

- **SeasyecN 的 Astro Retro Blog**：Canvas 动态扫描线、暗角、像素字体 `Press Start 2P`，整体像一台老式 CRT 显示器。  
  GitHub 搜 `SeasyecN/SeasyecN.github.io` 可看源码和截图。
- **像素风作品集/博客模板**：Next.js + Tailwind，8-bit/16-bit 像素艺术风格，适合喜欢“游戏怀旧感”的人。

### 方向 B：胶片 / 拍立得 / 书信体复古

- **“拾光 · 摄影集”**：CSS 瀑布流 + 拍立得卡片（随机旋转、hover 回正）+ 全局 sepia 褪色滤镜，照片详情页用 **书信体排版**：横格纸底纹、红色边距线、手写体落款。  
  在线 Demo：`https://jiaofu-lilac.vercel.app`。  
  这个方向和你“相册 + 旅行 + 家庭记忆”的内容匹配度最高。

### 方向 C：复古手账 / 物理质感

- **“折角、咖啡渍与拉珠开关”**：把网页做成一张有温度的旧剪贴簿——台灯拉珠开关切换暗黑模式、燕尾丝带书签、图钉标签、拍立得反光相纸效果。  
  地址：`jintaoblog.com/posts/79.html`。  
  这个方向交互细节最多，一周内只能取其“1～2 个元素”来做，不建议全盘复制。

### 方向 D：纸感 / 墨色安静复古

- **astro-theme-ink**：暖纸感、衬线标题、大量留白、单一强调色，比前三种更“克制高级”。它不是张扬的“复古”，而是旧书页式的安静。如果你说的“高级”更接近这种，可以优先考虑。

### 建议

以 **方向 B（胶片/拍立得）为视觉基底**，因为它天然适合相册和旅行；从 **方向 C 借 1 个细节**（比如拍立得卡片 hover 反光或纸张纹理）；整体排版保持 **方向 D 的克制**，避免像素风和手账风叠加导致“元素打架”。

## 8. 技术方案

### 8.1 整体架构

**纯静态站点（SSG/预渲染）**，不配后端和数据库。

所有内容以 Markdown 或 JSON 文件存放在仓库里，构建时生成 HTML/CSS/JS，部署到静态托管平台。

原因：预算和一周时间都不允许维护服务器；静态站没有运行时后端，成本几乎为零，也不会因为流量小而产生账单。

### 8.2 React + Vite 的具体选型

你指定了 React + Vite，这本身没问题。但需要区分“纯 SPA”和“预渲染/SSG”：

| 方案 | 适合度 | 问题 |
|---|---|---|
| **纯 Vite + React SPA**（`npm run build` 只出一个 `index.html` + JS） | 一周最快，但 **不推荐直接上线** | 微信爬虫抓不到 JS 生成的 `og` 标签，分享卡片会失效；私密页的 meta 也无法按页面定制 |
| **Vite + React + 预渲染/SSG** | **推荐** | 构建时为每个路由生成独立 HTML，`og` 标签、分享卡片、SEO 都能正常工作。代价是内容管理要按文件组织，而不是在后台点“发布” |

**具体路径**：优先直接使用现成的 **React 19 + Vite + TypeScript 博客模板**（例如 `TnTeQAQ/blog-template`），它已经处理了 Markdown 内容、路由、静态构建，`npm run build` 输出 `dist/` 可直接部署到 Cloudflare Pages / Vercel / GitHub Pages。

你在这个模板基础上改视觉和内容，是 **一周上线最现实的路径**。

如果模板的视觉和你的“复古”差距太大，可以换一个更接近的模板，或者只重写 CSS 和首页、详情页的布局，但 **保留它的构建、路由和内容管线**。

从零手写路由、Markdown 渲染、图片处理，一周内很难做到可维护。

### 8.3 微信分享卡片

必须在 **预渲染出的 HTML 的 `<head>` 里直接写入** `og:title`、`og:description`、`og:image`（HTTPS 直链，建议 1200×630）。

JS 动态插入无效，因为微信在页面加载初期就完成抓取。SSG 正好满足这一点。

如果某个平台不支持 SSG，微信分享就只能显示链接，这是选 React+Vite 时必须接受的取舍。

### 8.4 多语言（中 + 英）

界面文案用 **`react-i18next`** 或轻量 JSON 词典即可。

语种切换走 URL 前缀（`/zh/...`、`/en/...`），可分享、可刷新。

第一版只翻译导航和固定文案，内容级双语留到第二版。

### 8.5 私密内容

纯静态站上可用的方案：**StatiCrypt**（构建时用 AES-256 加密 HTML，浏览器端输入密码解密）。

它不需要后端，但安全边界是“防普通访客”，不是“防攻击者”。

第一版可以只对“家庭记忆”和部分工作项目启用，公开内容不加密。

### 8.6 访问统计

大陆可用的低成本/免费方案：

- **51.la**：国内老牌免费统计，接入一段代码即可。
- **Umami Cloud 免费版**：小站够用，界面干净，但官方云服务在国内的稳定性需要上线前实际测试。
- 备选：百度统计（大陆加载速度最好，但功能偏传统）。

第一版先用 51.la 或 Umami，**不要自部署**，自部署需要服务器，会打破“零后端”的前提。

## 9. 托管、域名与成本

| 项目 | 建议 | 月均成本 |
|---|---|---|
| 托管 | **Cloudflare Pages**（绑自有域名后国内访问相对可接受；免费额度：静态请求不限量、构建 500 次/月） | 0 元 |
| 域名 | `.com` 或 `.life`，年费约 60～100 元 | 约 5～9 元 |
| 统计 | 51.la 或 Umami 免费版 | 0 元 |
| 图片 | 随仓库走，用构建管线压缩；不上对象存储 | 0 元 |
| **合计** |  | **约 5～10 元/月**，远低于 100 元预算 |

### 大陆访问的诚实提醒

Cloudflare Pages 的默认域名在国内“时断时续”，**绑自有域名后会稳不少**，但不同地区、不同运营商效果有差异。

上线前用你的手机流量和家里 Wi-Fi 各测一次。

如果绑域名后仍然不理想，备选是 **GitHub Pages**（国内访问比 Cloudflare 默认域名稳一些，但比国内云慢）。

**不建议**为了大陆速度在一周内上国内云服务器 + 备案，备案本身就不止一周。

## 11. 风险与需要确认的事

1. **私密内容的真实安全等级**  
   如果家庭记忆或工作项目里有你 **绝对不能公开** 的信息，纯静态客户端加密不够，需要改用带后端的方案，但那一周上不了。  
   请确认：第一版的“私密”是否可以接受“密码挡住普通访客”的级别。

2. **微信分享是硬需求还是锦上添花**  
   如果是硬需求，必须走 SSG/预渲染，不能退回到纯 SPA。这会影响模板选择。

3. **“共同写”的时间点**  
   你说“未来可以家人朋友共同写”。第一版不做协作，但内容文件的结构要提前留好（比如每篇内容带 `author` 字段），否则第二版加协作时要返工。

4. **域名和名字是否今天能定**  
   名字不定，域名不能查，第 1 天的计划会往后滑。
